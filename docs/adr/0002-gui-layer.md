# ADR-0002 · 引入图形界面与界面模型层

| 项 | 值 |
| --- | --- |
| 状态 | 已采纳（Accepted） |
| 日期 | 2026-10-24 |

| 关联 | `docs/OUTLINE.md` §2.3 §4 §5.2 §10 |

本记录修订 ADR-0001 后的架构：在不破坏四层依赖的前提下，增加图形界面适配器与
GUI 无关的界面模型层。起因是用户调整优先级——**先做图形界面，再面向界面做编排算法**。

---

## 决策 1 · GUI 是一个适配器，不是新的一层业务

### 背景

OUTLINE §2.3 原本明确"不做图形界面"。当前需求变化：先交付可操作的桌面界面，
后续编排算法要围绕界面呈现来设计。若把界面逻辑直接塞进 `app/` 或 `cli/`，
会重演"一个 main 装全部逻辑"的老问题，也无法在将来替换成外部 GUI。

### 决定

新增两个目录：

| 目录 | 角色 | 允许 | 禁止 |
| --- | --- | --- | --- |
| `include/ordo/ui/` + `src/ui/` | GUI 无关的界面模型（`AppModel`） | 表单解析、调用 `TaskService`、把 `Task` 映射成展示行 | 任何 Win32 / 窗口类型 |
| `include/ordo/gui/` + `src/gui/` | Win32 适配器（主窗口、对话框、控件） | 创建窗口、读控件、调用 `AppModel`、显示 `Status` | 业务规则、直接读写文件 |

依赖方向：

```
cli/ ──────────────┐
                   ├──▶ app/ ──▶ { algo/, io/ }
gui/ ──▶ ui/ ──────┘
```

- `cli/` 维持现状，直接调用 `app/`。
- `gui/` 只能调用 `ui/`；`ui/` 只能调用 `app/` 与 `core/`。
- `ui/AppModel` 是**未来外部 GUI 的唯一接入点**：它只暴露 `std::string`（UTF-8）、
  `Result<T>`、`Status`，不出现 `HWND`、`wchar_t`、窗口消息。

### 后果

- **正面**：Win32 外壳可以整体替换（Qt、Web、ImGui），业务与表单规则不动；
  界面模型可以在没有窗口的环境下单元测试。
- **负面**：多一层转发；CLI 与 GUI 各自做一份参数/表单解析
  （两者输入语法不同，且都只调用 `TaskService`，不重复业务规则）。
- **约束**：`gui/` 不进入 `ordo.exe` 与 `ordo_test.exe` 的链接，保持 CLI 可移植。

## 决策 2 · 第一版 GUI 用 Win32 原生控件

### 背景

项目约定零第三方依赖、只用 MinGW + Makefile。用户要求"先实现最基础的，保留接口"。

### 决定

- 使用 Win32 API + 公共控件（ListView、Button、ComboBox、DateTimePicker）。
- 新增产物 `bin/ordo-gui.exe`，与 `bin/ordo.exe` 并存。
- 只支持 Windows；`Makefile` 在非 Windows 平台不构建 GUI。
- 不引入 Qt / ImGui / WebView2，也不新增资源编译器依赖。

### 后果

- **正面**：`mingw32-make` 即可产出可双击运行的 exe；无新依赖；控件行为由系统保证。
- **负面**：界面为 Windows 原生风格；高度定制的视觉效果需要自绘，本期不做。
- **触发重审**：需要跨平台 GUI，或需要可视化时间轴/拖拽编排时，在 `ui/AppModel`
  之上另写适配器，不改动本层。

### 备选方案

- **Dear ImGui**：观感现代、开发快，但需把第三方源码与 OpenGL 后端纳入仓库，
  违背零依赖约定。**否决（当前阶段）**。
- **本地网页界面**：HTML/CSS 最灵活，但需要本地 HTTP 服务或 WebView2，
  C++ 侧复杂度和系统组件依赖都更高。**否决**。
- **Qt**：本机未安装，体积与构建成本远超作业范围。**否决**。

## 决策 3 · 里程碑插入 M1.5

M1（基本要求）已验收。用户要求 GUI 先于编排算法，因此在 M1 与 M2 之间插入
**M1.5 图形界面**：

- 目标：`bin/ordo-gui.exe` 完成任务的增、删、改、查、完成、排序、统计；
  右侧预留"今日计划"区域，但**不显示假数据**。
- 完成判据：不依赖命令行即可完成全部现有业务；`mingw32-make test` 仍全绿；
  `docs/GUI-INTERFACE.md` 写明外部 GUI 的接入契约。
- M2（空闲时段 → 装箱 → 冲突告警）顺延，且其接口要围绕 `ui/AppModel` 的
  计划视图设计。
